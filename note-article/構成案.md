# note記事 構成案（3パターン）

年表（`年表.md`）の事実をどう並べるかの選択肢。**どれを選ぶかで、ヒアリングで深掘りする箇所が変わる。**

---

## 案A｜「境界線」型 — AI導入前後の対比を軸にする

> **想定タイトル**: 「431コミット目で、個人開発が変わった話」
> **想定読者**: 個人開発者 / AI活用に関心のある層
> **想定文字数**: 6,000〜8,000字

### 構成
1. **導入** — 1枚のグラフから始める（コミット書式の月別割合表）。「0%が突然88%になった日がある」
2. **なぜ作り始めたか** — Glide期。ノーコードで作った最初の形（スクショ）
3. **手作り期の431コミット** — `Update index.html` の羅列。parts.htmlを53回書き直した話
4. **限界** — 1月に203コミット打っても終わらなかった
5. **境界線 2026年2月1日** — Claude Code導入。CLAUDE.mdを置くという発想
6. **何が変わったか** — 2/21の「1日で自動化元年」、クローラー9本、126姉妹サイト、YouTubeポータル
7. **変わらなかったもの** — 最初に書いたmain.gsが今も朝のメールを送っている
8. **まとめ** — 数字で締める（948コミット / 144日 / 40ページ）

### 強み
- **データの説得力が突出**。「AIで開発が変わった」を感想でなく実測で示せる記事は稀
- 拡散しやすい。noteでこの層は読者が厚い

### 弱み
- FIAT 500への愛が背景に退く。同好の士には刺さりにくい
- 「AI礼賛」に読まれないよう、失敗も入れるバランスが必要

---

## 案B｜「1年の開発記」型 — 作ったものを時系列で追う

> **想定タイトル**: 「FIAT 500好きが1年でサイトを作り続けた記録」
> **想定読者**: 同じ趣味の人 / クラシックカー層 / サイトのユーザー
> **想定文字数**: 5,000〜7,000字

### 構成
1. **導入** — 今のサイトの姿（スクショ）。ここまで来た
2. **第1幕 Glide期** — 何もわからないところから
3. **第2幕 手作り期** — 地図、イベント掲示板、統計、そしてパーツ検索
4. **第3幕 拡張期** — 126姉妹サイト、オーナーの物語、配線図ビューア、装備手帳、YouTubeポータル
5. **裏側** — 毎日動いているクローラーとAI翻訳の話（軽めに）
6. **これから** — 残っている構想

### 強み
- **サイトの宣伝として機能する**。読者がそのままユーザーになる導線
- 40ページ分のスクショが全部使える。ビジュアルが強い
- 書きやすく、事実だけで成立する

### 弱み
- 「作りました」の羅列になりやすく、山場を作りにくい
- 技術層への訴求は弱い

## 案C｜「失敗と乗り換え」型 — 詰まった所だけを書く

> **想定タイトル**: 「1年で3回作り直した — 個人サイト開発の失敗記録」
> **想定読者**: 個人開発者 / これから何か作ろうとしている人
> **想定文字数**: 6,000〜8,000字

### 構成
1. **導入** — 「Glide、GAS、Firebase。この1年で捨てた技術の話をします」
2. **捨てた① Glide** — ノーコードで始めて、なぜ離れたか
3. **捨てた② GAS配信** — 2025-11-24、gas/sites/ から引っ越した日
4. **意地でやった時期** — parts.html 53回書き直し。1月の203コミット
5. **捨てた③ Firebase Auth** — 1/31に導入、2/27にSupabase Authへ。1ヶ月の寿命
6. **止まった月** — 2026年5月、7コミット。何があったか
7. **残ったもの** — 捨てなかったmain.gs、そして今動いている11本のワークフロー
8. **まとめ** — 捨てる判断のコスト

### 強み
- **一番「読み物」として面白い**。noteは失敗談の需要が大きい
- 誠実な記事になる。AI導入も「道具のひとつ」として自然に収まる
- 案Aのデータもここに組み込める

### 弱み
- **ヒアリング依存度が最も高い**。「なぜ捨てたか」は全部本人の中にしかない
- 5月の空白が語りにくい内容だった場合、構成が崩れる

## 【2026-08-03 更新】案D｜「架け橋」型 ← **これを推します**

ヒアリング（プロフィール・動機・Glide撤退理由・5月の真相）を受けて追加。
**A〜Cはヒアリング前の案。今はこの案Dが最善だと考えます。**

> **想定タイトル案**:
> - 「57歳・IT素人が、クラシックカー仲間のためにサイトを作った1年」
> - 「もらうばかりだったから ― 948コミットの記録」
> - 「開発が止まった月、私は九州にいた」
>
> **想定文字数**: 8,000〜10,000字

### なぜ案A〜Cではなくなったか

判明した事実で、話の重心が**技術から動機に移りました**。

- 「57歳・IT素人・開発経験ゼロ」というプロフィールは、案A（AI対比）の枠に収めるには強すぎる
- 動機が「もらった恩を返したい」「オーナー同士の架け橋になりたい」という**明確に人間的なもの**だった
- そして5月の空白の正体が**九州一周2,200km・仲間に会いに行った9日間**だった

これで**始まりと終わりが同じ場所に着地する円環構造**が組めます。
「オーナー仲間との繋がりを強くしたい」で始まり、「実際に会いに行った」で終わる。
技術的な失敗も、AI遍歴も、その途中経過として自然に収まります。

### 構成

**第0章｜谷から始める**
コミット月別グラフを最初に見せる。5月だけ7件。「この月、何があったと思いますか」で引く。

**第1章｜57歳、IT素人**
プロフィール開示。会社員、スキルゼロ、サイト開発経験なし。
FIAT 500に乗って5年。先輩オーナーに助けられ、ネットで仲間ができ、生活が変わった。
**「もらうばかりだったので、少しでも還元したい」**
着火点は「他のオーナーの仕様、どうなってるんだろう？ 私が知りたいなら、みんなも知りたいはず」

**第2章｜Glide ― 最初の形**（スクショ）
AIに相談してGlideを紹介される。オーナー仲間10人弱がテストデータを入れてくれた。
公開しようとしたら**無料枠のユーザー数上限**。基本無料で運用する方針だったので断念。
→ ここで「仲間が手伝ってくれた」事実を置いておくと、終章の九州が効く。

**第3章｜彷徨**
Softr + Firebase + Sheets を検討 → 費用でうまくいかず。
**GAS + Firebase + スプレッドシート**で本番リリース。2025-11-11、リポジトリ開設。

**第4章｜431コミットの手作り期**
`Update index.html` の羅列（実物を貼る）。ブラウザで直接書き換えていた時代。
地図、イベント掲示板、統計、そしてパーツ検索。
**parts.html を53回書き直す**（うち27回が1月）。1月は203コミット打っても終わらなかった。
相談するAIも Gemini → ChatGPT → Manus と渡り歩くが、噛み合わない。

**第5章｜2026年2月1日**
Claudeに行き着く。**431件目まで0%だったコミット書式が、432件目から88%に**（表を貼る）。
2/4に `CLAUDE.md` を置く。2/21、**たった1日で**Actions自動更新・AI翻訳・クローラー3本。
2/18に126姉妹サイト。3/6にクローラー5本を同日Actions化。

**第6章｜作れるようになって、何を作ったか**
オーナーの物語（stories）、配線図ビューア、装備手帳、YouTubeポータル。
**全部「オーナー同士を繋ぐ」ための機能**だったと気づかせる。動機は1ミリもぶれていない。

**第7章｜そして、谷の話**（クライマックス）
第0章の伏線回収。5月6日〜15日、九州一周2,200km。
150台を超えるコミュニティの仲間に、実際に会いに行った。
**開発が止まった月は、サイトを作った目的が実現した月だった。**

**第8章｜今も作っている**
最初に書いた `main.gs` が今も朝のダイジェストメールを送り続けている。
948コミット、144日、40ページ。そして今日も装備手帳をいじっている。

### 強み
- **山場が明確**（第5章のデータ、第7章の反転）で、8,000字超でも読者が離れない
- 技術層にも同好の士にも届く。「57歳・素人」が広い共感を作る
- 案A・B・Cの要素が全部入っている（データ／サイト紹介／失敗談）
- **サイトへの導線として機能する** — 読んで登録したくなる終わり方

### 弱み
- 長い。8,000〜10,000字は覚悟が要る（前後編に分けても成立します）
- 第7章が効くかは、九州のエピソードをどれだけ簡潔に書けるかによる（既存note記事へリンクして深追いを避けるのが得策）

## 【参考・旧】ヒアリング前の推奨

**案C（失敗と乗り換え）をベースに、案Aのデータを武器として組み込む** 形を推していました。

理由:
- 案Aの「431→432でコミット書式が変わる」は**単体で1記事になるほど強い素材**だが、それだけだとAI活用記事の量産品に埋もれる
- 案Cの骨格に案Aのデータを入れると、「失敗を繰り返した果てにAIに行き着いた」という**流れのある物語**になり、他の記事と差別化できる
- サイト紹介（案B）の要素は、各章のスクショで自然に果たせる

ただし案Cは**5月の空白と各撤退理由が語れることが前提**です。ここが書けない事情があるなら案Aに寄せます。
