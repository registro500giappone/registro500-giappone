# パーツ位置決めガイド（3D立体パーツカタログ・全パーツ展開用）

3Dビューア（index.html）のパーツマーカー `pos3d` を決めるときの座標系・ランドマーク・手順・出典の型。
電装11部品（ウインカー系）で確立したワークフローを、今後 エンジン／駆動系／足回り／外装／内装 の全パーツに適用する。

## 1. 座標系（f.json の pos3d）

- 単位: mm（実車スケール）
- **x**: 前軸中心 = 0、後方が正（後軸 ≈ 1833）
- **y**: 車体中心 = 0、**左が正**（進行方向に向かって左＝運転席側）
- **z**: 地上高（接地面 = 0）

### モデル実測ランドマーク（body_f_v2.glb・check_model.py で取得）

| ランドマーク | 値 |
|---|---|
| 車体X範囲（ノーズ先端〜テール） | -448 〜 2461 |
| 前軸 / 後軸 | x = 0 / 1833 |
| 車体幅（最大） | y = ±658（トランク内壁 ≈ ±430） |
| ホイール中心高・タイヤ半径 | z = 247 |
| ルーフ頂 | z = 1356 |
| 前部トランク床 / エンジンルーム床 | z ≈ 420 |
| ダッシュパネル面 | x ≈ 470、z ≈ 760〜800 |
| バンパー | z ≈ 330〜380 |

## 2. 位置照合の2段階（f.json スキーマ）

| 段階 | フィールド | 意味 |
|---|---|---|
| 文献照合済み | `pos3d_source` に出典を記載 | 図面・マニュアル・写真から特定した概算（±50〜100mm）。カタログ用途には十分 |
| 実車照合済み | `pos3d_verified: true` | オーナー実車確認が正本。`?edit=1` の矢印キー微調整で確定 |

新規パーツ追加時は必ず `pos3d_source` を付ける（出典なしの当てずっぽう座標を作らない）。

## 4. ワークフロー（1グループ分の型）

1. **部品リスト作成**: グループ（下表）の代表部品を選定し、`parts_query`（q + category）で parts.html の検索結果が出ることを確認
2. **文献調査**: §3の一次資料＋Web写真で各部品の定性位置を確定（型式差・年式差に注意。F型を基準とする）
3. **mm座標化**: §1のランドマークから pos3d を算出、`pos3d_source` に出典を記載
   - モデル自身に対応する形状があるパーツ（ランプ・ミラー・マフラー等）は、GLB頂点クラスタリングで実中心を測ってそこへ合わせる（pygltflib + check_model.py の node_positions_mm で領域指定→平均。電装ランプ4灯で実施済みの型）。文献位置とモデル形状が数十mmずれる場合はモデル実測を優先（表示上の整合が目的のため）
4. **スクリーンショット自己検証**: ローカルサーバー（repoルートで `python -m http.server 8123`）→ Playwright で `http://localhost:8123/wiring/index.html` を開き、シースルー＋部品リストから各部品へ flyTo → 複数アングルで車体との整合を目視 → ずれていれば座標修正して再確認
5. **ユーザー最終レビュー**: 複数アングルの画像を提示し OK/NG のみもらう（NG分は `?edit=1` で微調整 → `pos3d_verified: true`）

## 5. 全パーツ展開マスタ（グループ計画）

groups.id → parts DB カテゴリ（7分類）の対応。この順で展開する想定。

| group id | label_ja | parts.html カテゴリ | 代表部品の候補 |
|---|---|---|---|
| electrical | 電装 | 電装・ライト・点火系 | ✅済: バッテリー/ヒューズ/リレー/SW/ランプ類。今後: ダイナモ・レギュレーター・スターター・コイル・ディストリビューター・ホーン・ワイパーモーター（大塚図に全て配置あり） |
| engine | エンジン | エンジン・吸排気 | シリンダーヘッド・キャブレター・エアクリーナー・マフラー・オイルフィルター・燃料ポンプ（エンジンルーム x≈1900〜2400） |
| drivetrain | 駆動系 | 駆動系・ミッション | クラッチ・ミッション・ドライブシャフト（x≈1500〜1900） |
| chassis | 足回り | 足回り・ブレーキ | ブレーキドラム・マスターシリンダー・ショック・リーフスプリング（前軸/後軸まわり） |
| body | 外装 | 外装・ボディ・幌 | 幌・バンパー・モール・ミラー・エンブレム |
| interior | 内装 | 内装・インテリア | シート・ステアリング・シフトレバー・ペダル・内張り |

- 燃料系（タンク=前部トランク右・センダー）は engine か electrical に混ぜず、実装時に判断
- 系統（systems）は配線DBの16系統展開と歩調を合わせる。機械系パーツは systems なし（group のみ）でもマーカー表示できるよう index.html 側の前提を確認すること

## 6. 既知の事項

- **右ハンドル問題は解決済み（2026-07-09発見→同日修正）**: 両GLBがRHD状態だったのを `tools/mirror_glb.py` で直接Y軸ミラーしLHD化（実測: F=左139/右17、L=左1677/右95）。wheels JSON（L型の操舵非対称分）とindex.htmlのMODEL_INFO.l.wheelsもy反転済み。prep_model.py の符号も vy=+x に是正済みで、次回ソースから再生成してもLHDになる。

## 7. 検証コマンド

```bash
# モデル座標回帰チェック
cd wiring/tools && python check_model.py ../assets/body_f_v2.glb --wheelbase-mm 1840

# ビューア起動（repoルートから）
python -m http.server 8123   # → http://localhost:8123/wiring/index.html
```
