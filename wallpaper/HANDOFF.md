# 壁紙ジェネレータ HANDOFF（正本）

> **これは何か**：登録されたメイン写真から、オーナーが自分で待ち受け画像を作れる機能。
> 第一弾は**オールタイル図鑑**＝全登録車を敷き詰め、ログイン済オーナーだけが自分の1台をハイライトできる。
> **現在地：段1（絵の設計）完了・段2（画面の実装）未着手。**

## §2 並び順のロジック（正本）

### 2-1 色順は「案3」で確定

```
白 → クリーム → グレー → 黄 → 橙 → 赤 → 紫 → 紺 → 青 → 水色 → 緑 → 黄緑
```

- ⛔**案2（グレーを黄の後）は不採用**＝水色と青が離れるため（ユーザー判断）。
- ⭐**グレーはクリームの隣**＝橙の後に置くと「余り物・色不明」に見えるという指摘から。

### 2-2 グループ内は濃淡＋1つおき反転

- **申告された `body_color` が主**。66種の自由記述を辞書で13グループへ正規化（156台）。
  - 「→」は後ろを採用、「／」「/」「・」は先頭を採用。
- **空欄13台だけ写真から推定**（中央帯を quantize して最大クラスタの色相で判定）。
- ⚠️**濃淡は写真の平均色では測れない**（空・アスファルト・紅葉・建物を拾う）。
  **申告グループの色相域に該当する画素だけ**を抽出して `L = V*(1-S/2)` の平均を取る。
- ⭐**1グループおきに向きを反転**（淡→濃／濃→淡）＝境目が必ず「濃と濃」「淡と淡」で接し、169台がひと続きのグラデーションになる。
  - 実測の向き：白45↓ / クリーム16↑ / グレー11↓ / 黄31↑ / 橙4↓ / 赤11↑ / 紫1↓ / 紺13↑ / 青7↓ / 水色20↑ / 緑5↓ / 黄緑5↑

### 2-3 ロゴを両端に置く理由

⭐**この置き方は色順の設計があって初めて成立する。** 並びが白から始まるので、白地の500ロゴが先頭で白い車の列に紛れる。
2枚を並べると「明るいタイル2つの塊」になり、末尾だと**余った枠の埋め合わせ**に見えた。両端へ離すとその両方が消える。
本の表紙と奥付の構造で、169台のうち126は6台という実態とも順番が合う。

⚠️**唯一の弱点＝126と500が離れるので、2つのロゴを対にして見せる用途には向かない。**その必要が出たら末尾に2枚まとめる案（L5）へ戻す。

## §3 バリエーション＝4通り（確定）

|  | 並び | ハイライト | 沈める |
|---|---|---|---|
| V1 | 登録順 | なし | しない |
| V2 | 色順 | なし | しない |
| V3 | 登録順 | あり（自分の1台） | 22% |
| V4 | 色順 | あり（自分の1台） | 22% |

ログイン時にハイライトを外せば V1・V2 と同じ絵になるので、**絵として存在するのは4種類**。

## §4 実データから出た分岐（⏳段2で必ず実装する）

DB実測（2026-09-04・総170台／オーナー紐付け116台／113ユーザー）：

1. **2台以上を登録しているオーナーが3人**（いずれも2台）
   → **どちらをハイライトするか選ばせる。** 2つ置くと2×2が2箇所になり「自分の1台」の意味が崩れる。
2. **自分の車が図鑑に載っていないオーナーが1人**（`sns_share_optout` のため）
   → **黙って失敗させず理由を出す**（「SNS掲載をオフにしているため図鑑に載っていません」＋設定への導線）。写真未登録の車は現時点0台だが同じ扱い。
3. **端末ごとの画面サイズ**
   → 1179×2556 は iPhone Pro 系。⭐**ブラウザで生成する以上その端末の実サイズで組める**（台数から列数を選ぶ仕組みなので画面が変われば格子も追随する）。
   **「見ている端末のサイズで作る」を既定にするか、代表サイズから選ばせるか**が決めどころ。

## §6 不変条件・技術上の罠（⛔踏まない）

- ⭐**スプライトシート方式が CORS を回避している。** 169台を1枚のWebPに焼いて**自ドメインから配信**するので canvas が汚染されない。
  ⚠️**Firebase Storage には CORS が設定されていない**（`Access-Control-Allow-Origin` なし）＝ブラウザから直接読むと canvas が汚染され `toBlob`/`toDataURL` が SecurityError で落ちる。**第二弾で元写真を直接使うなら、先に CORS 設定かプロキシが要る。**
- ⚠️**メイン写真は長辺1000px**（`edit.html:829` の cropper で 1000×1000 にクロップされる）。1枚デカ使いは破綻するが、タイルなら余裕。
- ⚠️**iOS Safari の canvas 総ピクセル上限は約16.7Mpx。** 現行スプライトは 3328×3328 = 11.1Mpx で収まっているが、台数が増えると超える。
- ⚠️**iOS Safari は `<a download>` が効かない**＝保存は長押しの導線が要る。
- ⛔**スプライトに入れるのは `sns_share_optout` でない車だけ**（掟＝ `MEMORY_watchlist.md` 冒頭）。
- ⚠️**横倒しの写真が3台**（DOC_47・DOC_96・DOC_98）＝いずれも時計回り90度で正しくなる。EXIF の回転情報が失われて横長のまま保存されている。
  補正表＝`wallpaper/proto/rotate-fix.json`。⚠️**元写真そのものが傾いているので、車両ページでも横倒しに表示されているはず**＝根本の直し方は別の判断（撮り直し／管理画面で回転を保存／表示側で自動判定）。
  全169台をエッジ量で走査済みなので**他に同じものはない**（DOC_12 は真上からの俯瞰写真で向きは正しい）。
- ⛔**導線（メニュー・リンク）は付けない。** ユーザーの明示指示があるまで（CLAUDE.md の掟）。

## §7 試作の在り処と再現手順

```
wallpaper/proto/
  build_sprite.py   Supabase REST(公開キー) → Firebase並列DL(ローカルキャッシュ) → 256px角 → 13列スプライト
  make_phone.py     色の正規化・濃淡測定・並び順・レイアウト・見本生成（段2の移植元はここ）
  make_page.py      検版ページ（Artifact用HTML）の生成
  rotate-fix.json   横倒し写真の補正表
```

- 実行は `wallpaper/proto/` で `python build_sprite.py` → `python make_phone.py`。
  `cache/` にDL済み写真、`out/` にスプライトと manifest、`out/phone/` に見本が出る（いずれも gitignore 済み）。
  ⚠️別の場所へコピーして走らせるなら、ロゴ画像を探すために環境変数 `R500_ROOT` に repo ルートを渡す。
- 生成物：`sprite-v1.webp`(2.33MB) / `manifest-v1.json`(17.3KB) / 見本JPEG群。
- 原寸の見本JPEGは公開repo外の `registro500-notes\wallpaper-mock\phone\` にコピー済み。
