# エンジン妄想シミュレーター（仮称）HANDOFF

## §1 ゴール（確定）

1. **「いまの1台」→「何をどう変えたら」→「おおよそどう変わるか」**を、数値入力なしに、プリセットの選択だけで見せる。
2. 出発点は純正だけでなく**既に改造済みの状態**（例：650cc化済み）からも選べる＝「次に何をするか」を考えているオーナーが対象。
3. 結果は曲線の重ね描き＋**差分の物語**（街乗り／回した時／アイドル／始動性の変化を文章で）＋**足を引っ張っている所の名指し**（例「キャブが先に詰まっているのでカムだけでは伸びない」）＋副作用の注意（熱・圧縮比と燃料・スプリング・ピストン干渉）。
4. 多少のエンタメ性を持たせる。

## §5 計算核（段1・2026-09-17 実装）

**ファイル**＝`sim.js`（純粋関数 `simulate(spec, rpmList, {cal})`・ES module・Node/ブラウザ共用）／`engines_stock.js`（純正4機の諸元＝校正用）／`engines_abarth.js`（Abarth 595・595 SS・695 SS＝スポーツカム側の校正用）／`test_sim.js`（純正の再現）／`test_abarth.js`（純正＋Abarth の一覧・`-v` で曲線・第1引数に JSON で cal 上書き）／`test_tuning.js`（改造の方向テスト）／`diag.js`（感度診断）。実行＝`node test_sim.js` ・ `node test_abarth.js` ・ `node test_tuning.js`（1機 0.1 秒）。

**模型の中身**（0次元 充填・排出＋慣性）：クランク角 0.25° 刻み・6 サイクル収束。シリンダー単一領域の第一法則／Wiebe 燃焼（a=5, m=2, 燃焼期間 55°+0.006·rpm）／Woschni 簡易熱伝達（×2.5）／Chen-Flynn 型 FMEP／圧縮性オリフィス（バルブ・ベンチュリ）／**吸気ランナーと排気管の運動量方程式（ラム効果・掃気の慣性）**＝⭐これが無いと長作用角カムが常に損になる（実装時に実証）／吸気の加熱（低回転ほど大）・ベンチュリ流速が低いときの混合気の質・回転数²で増える排気背圧。リフト曲線は余弦で、カタログ角を checkLift（既定 0.5 mm・純正は検査クリアランス値）でのリフトとみなし座面まで延長。

**【2026-09-17 更新・500F の納得感】** ユーザー要望「500F だけ挙動が違う＝一番メジャーな型式なので、プロに突っ込まれても耐えられるレベルに」を受け、一次資料（Caratteristiche 文書の画像ページ p.30・p.33・p.39・p.7・p.84）を直読して入力値と模型を直した。全経緯と数表は `ref/stock_specs.md` §⑥。要点：
1. **バルブ径 32/28・配分線図 25/51-64/12（検査 0.39）は図36・図38で確定**（Web の異説 30/27 は不採用）。
2. **バルブリフト 8.4 mm**＝p.33 バルブスプリング表の検査長（閉 38.5 → 開 30.1、内スプリングも 35.5 → 27.1＝差 8.4）。Axel「Camshaft lift 5.8」はカム山＝ロッカー比 ≒1.45。
3. **checkLift ＝ 検査クリアランス − 運転クリアランス**（500: 0.39−0.15＝0.24／126: 0.625−0.20≒0.42）に定義を修正。
4. ⭐ **上振れの正体＝測定条件**。Fiat は同じ 500 に「con ventilatore（ファン付）」と「SAE（総出力）」の2値を併記（500F: DIN 18CV／SAE 22CV・トルク 3.1／3.6 kgm）。段1の模型はファンを持たず **SAE 寄りに出ていた**。→ **冷却ファン＋発電機の吸収動力 `kFan_kW·(rpm/4600)³` を追加**（`spec.accessories.fan=false` で SAE 相当）。

**限界（画面で明記する）**：①純正4機は ±5%・ピーク回転 4600〜5000（実車 4500〜4800）②**スポーツカム側は Abarth 3機で校正済（2026-09-17・下の【Abarth 校正】）**＝ファン込みで −1〜−12%・ファン無しで +16〜−1%＝**公表値はその間**。トルクは −11〜−16%（VE の上限 0.83＝吸気共鳴を持たない模型の限界。5.2 kgm＝BMEP 10.8 bar は共鳴か総出力表記でしか出ない）。ram 効果の感度は弱い（ランナー長 0.12→0.3 m で ±1%）③排気管の脈動は慣性のみ（共鳴は無い）④ノッキング・スプリングの追従限界・ピストンとバルブの干渉は計算しない＝閾値で警告 ⑤キャブは「ベンチュリ径×係数」だけ（ジェットの合否は見ない）⑥ロッカー比（1.45〜1.5）は一次資料に数値が無い＝スプリング検査長からの逆算 ⑦500 系と 126 系の吸排気系の差（ポート径・マフラー径）は資料にもDBにも数値が無い（db-checker で確認済）＝共通係数で扱っている。

**【2026-09-17 Abarth 校正】** 旧「595SS 相当 −20%」は諸元が一般知識（CR9・33mm弁・checkLift 0.5・純正マフラー）だったのが主因で、公表諸元に置き換えたら −6% に収まった。**当てるために変えたのは2つだけ**（⛔純正4機の校正値 `DEFAULT_CAL` は1つも触っていない＝純正の結果は不変）：
1. **`intake.mixMin`（キャブの属性）**＝「ベンチュリ流速が低いと混合気の質が落ちる」項の下限を、加速ポンプ付きキャブ（Solex PBIC・Weber DGF/DCOE 等）は 0.8 にする（純正 26/28 IMB＝ポンプ無し＝`cal.mixMin` 0.6 のまま）。根拠＝旧模型では **595 SS（ベンチュリ28）の低速トルクが 595（同24）より低く出た**（39 vs 42 Nm）が実車は逆（5.2 vs 5.0 kgm）＝大きいキャブへの罰が強すぎた。⚠️ `cal.vMixRef`・`cal.mixMin` を全体で緩めると 500F の 2500rpm が +20% になり Fiat 図45 の形（1500→2500 で立ち上がる）が消える＝⛔全体では触らない。
2. **`spec.cal = { kValveIn: 1.0, kValveEx: 1.0, runnerXi: 0.7 }`（ポート加工済みヘッドの属性）**＝595 SS の「re-worked inlet ports」・吸気弁 34（純正 32）。段2ではチューニングヘッドのプリセットがこれを持つ。
- Abarth の角は運転クリアランス 0.20 で測った値＝`checkLift: 0.05`（カタログ角＝座面角）。⭐**店のカタログ角も「どのクリアランスで測ったか」で作用角が 20°以上変わる**＝段2のプリセット正規化で `checkLift` を必ず持たせる（D'Angelo の「con gioco 0,25／0,30」表記が手がかり）。
- 感度掃引の結論＝**どの全体係数も5機を一緒に動かすだけで Abarth だけを持ち上げる項は無い**（`kValveIn`・`kHeat`・`cdVenturi`・`fmep`・`kFan` いずれも純正 +3〜4% と抱き合わせ）。残る差は測定条件（DIN/SAE）と共鳴の不在＝これ以上は追わない（§2「絶対値は追わない」）。
- 差分の再現＝595→595 SS は模型 +12%（公表 +18%）・595 SS→695 SS は +11%（公表 +19%）＝**改造の効き目は実車の公表差より小さめに出る**（同じ 34/28 弁のまま排気量とキャブを増やすと弁で詰まる計算）。画面では「控えめに出る」と断る。
- 出典の一覧＝`ref/stock_specs.md` §⑦。⚠️ Abarth の一次資料（libretto）は手元に無い＝Web 転記どうしの突き合わせ。

**プリセットの決め方（§0 の方針の実体）**
- カムは4角＋バルブリフト（カム山×**1.5**）＋`checkLift` に正規化。店が基準を書かない品は 0.5、D'Angelo は「con gioco 0,25」から **0.10**（0.25−運転 0.15）＝同店の基準未記載品にも同じ値を仮定して `assumed` に明記。FD の 38/78・55/85 はリフト未記載＝近い Axel 品の値を借用（`assumed`）。

### 7-11 回転の上限＝取説の「各ギア最大許容速度」（2026-09-18 ユーザー指示「aで」・実装済）

ユーザーの実車指摘＝「リアルの談合坂では、素の500ではトルク不足で4速では速度を保てずに減速していく。3速で最高回転で何とか登っていく。これがボアアップ欲求の源。いまのシミュレータだとスイスイ登ってしまう」。

- **上限の出所＝取説の「各ギアの最大許容速度」**。500F なら 23/40/65/95 km/h → 4725/4591/4692/4616 rpm ≒ **4650**。7型式すべてに `presets.js` の `revLimit: { rpm, src }` を置いた（500N 4400／500D 4650／500F 4650／GIA 4650／500R 4950）。⚠️**126 の 2 件（126A 5050・126A1 4725）は取説の裏付けが無い `assumed`**＝500 の 5 型式で「許容速度の回転 ÷ 公称回転」が 1.01〜1.10 だったことから 1.05 を採った。
- **実装＝物理式ではなく曲線を切る**。`vehicle.js` の `capRes(res, rpmCap)` が上限より上の点を捨て、上限ちょうどの補間点を足す。`torqueAt` は最後の点より上で 0 を返すので、駆動力・定常速度・ギア選び・ギア表の「—」・最高速が**全部自動的に上限を守る**＝レブリミッターと同じ働き。上限の値は `revCapRpm(built, res)`＝純正なら `revLimit.rpm`、**改造カムなら「回し続けられる回転」＝最高出力の回転の 500rpm 下**（25rpm 丸め・純正の許容回転を下回らない）。⚠️初版は「最高出力の 500rpm 上」→ ユーザー実測で「最高出力の回転」→ さらに「一瞬なら 5500 でも登り続けるのはせいぜい 5000」（Colombo & Bariani ロード・ミディアム＋純正マフラー・6000 はレース仕様）で 2026-09-18 に **−500** に落ち着いた。⛔坂は連続運転なので「一瞬回せる回転」を上限にしない。
- ⛔**上限が上がるのはカムを換えたときだけ**＝ボアアップや排気だけでは回るようにならない。この一文は `drive.html` の限界の節に出典つきで出している。
- **踏んだ罠 3 つ**（同じ轍を踏まないため）：①`accelerate` が `policy.shiftUp`（5000）を直接見ていたため、上限 4650 の車がレブに当たったまま変速せず **0-400 が 26.0s → 62.8s に破綻**した。→ `Math.min(policy.shiftUp, redline(res) * 0.98)` を `accelerate` と `pickGearForSpeed` の両方で使う。②`torqueAt` の上端に 2% の猶予があり「上限 4650」と書きながら画面に 4746rpm が出た。→ `rpm > last.rpm` で厳密に 0。③`steadySpeedInGear` の釣り合い点が「余力が尽きた最初の速度」だったので上限を超えた。→ **まだ余力が残る最後の速度**に変更。⭐**②③はどちらも「画面の数字どうしの食い違い」＝7-7 と同じ型**。
- **検品**（`test_vehicle.js` / `test_scenes.js`）は**画面と同条件**にした＝`capped(id, choices)` ヘルパーで `capRes(raw, revCapRpm(b, raw))` を通してから測る。新しい判定＝談合坂で 500F 純正が 70km/h 未満まで落ちる／**2人なら 3速に落ちる**／3速の頭打ちが取説の 65km/h と ±3km/h。⚠️**1人だと 3速に落ちない**（5% が 1.8km しかなく 64km/h まで落ちきらず 4速のまま 66km/h）＝ユーザーの言う「3速で最高回転」は 2人・満載・疲れたエンジンの側で再現される。

### 7-14 案B（出力曲線の形）＝検証したうえで⛔見送り（2026-09-18 ユーザー「やった方がいいならやって」→ 判断＝やらない）

### 7-15 入口を2つに分ける＝エンジン編と「ミッション・タイヤ編」（2026-09-19 ユーザー確定・第1弾ぶん実装済）

- ⭐**5速化を追加した**（`presets_vehicle.js` の `FIFTHS`）＝**ミッションの種類とは独立の欄**にした。1速の比が型式で違う（3.273／3.70／3.25）ことと直交するので、掛け算で選択肢を増やさずに済む。実物のキットも「既存の 1〜4速はそのままで5速だけ足す」ものなのでこの形が正しい。⛔**「5速ミッション」という別のギアボックスを作らない**。比＝**26/35＝0.743**（FD Ricambi VB1101「Gearbox Stradale 5 Speed Conversion Kit」・適合は 500 N/D/F/L/R・ジャルディニエラ・126・BIS・Bianchina）。⚠️**店は歯数 35/26 しか公表していない＝比の数値は算出した `assumed`**。効き方＝80km/h で 4速 3887rpm → 5速 3300rpm（15%減）、最高速は純正 96→99km/h・まず650 96→110km/h、**談合坂では5速に入らない**（登りでは使えない）。⭐**理由＝すでに5速のオーナーがいるので、その人が自分の車として設定できる必要がある**（ユーザー指摘）。

### 7-16 舞台の見せ方＝カメラを引く／縮図の点を車体にする（2026-09-19 ユーザー採用・実装済）

ユーザー指摘＝「**坂で距離が開いて画面いっぱいになると、間隔そのままで数字だけが増えていく。車を小さくして視覚効果を増すのはどうか。負荷の問題があるなら他の案も聞きたい**」。

- **負荷は増やさない**＝広げたぶん破線（20→50→100m）と電柱（50→100→200m）の間隔を粗くして、**画面に出る本数を一定に保つ**。車の絵は拡大縮小するだけで画像の読み込みは最初の1回のまま。⭐これがユーザーの負荷懸念への答え。
