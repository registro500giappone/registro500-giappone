# 上面図の線画を元図から起こす一式（2026-08-19）

`ref/blueprint_4views_hi.png`（1536×1024）の**上面図**から `wiring-img/car-top-v7.svg`（詳細）と
`car-top-v7s.svg`（骨格）を作る。**このディレクトリを cwd にして**順に実行する。
中間ファイル（`*.npy` / `*.pkl` / `*.png`）は gitignore 済み。

```
python hi_mask.py      # 局所コントラストで線だけのマスクを作る → hi_mask.npy
python hi_half.py      # 対称軸を測る（y=753.00 / sd 0.32px）＋上下半分を見る
python hi_trace.py     # 芯線化 → ポリライン        → hi_polys.pkl
python hi_svg.py 6.0  20 ../../../wiring-img/car-top-v7.svg    # 詳細（全部）
python hi_svg.py 34.0 20 ../../../wiring-img/car-top-v7s.svg   # 骨格（長い線だけ）
python make_top_page.py                                        # 閲覧ページ _top_view.html
```

`hi_svg.py` の引数は `最小の線長(出力px) 除外する線の番号(カンマ区切り) 出力先`。
**`20` は元図に入っている作図の補助線**（ボンネットを横切る中心線）。番号は `hi_trace.py` が
長い順に振るので、**元図やパラメータを変えたら番号は変わる**。確認は `hi_look.py` 相当を
書き直すか、`hi_polys.pkl` を読んで座標で当たりを付ける。

## 決めごと（変えるときは HANDOFF §5d を読んでから）

- **座標系**：原点＝元画像 (621, 551)＝車体インクの左上。**1出力px = 元画像2px**。
  較正は `S, LAT, CY = 150.5, 153.4, 101.0`（`make_top_review.py` が正本）。
- **中心線より上（車の右側）だけを採り、鏡像で左を作る**。左右は厳密に対称になる。
  → **左右非対称な物（ハンドル・計器）はこの経路に乗らない**。`make_top_review.py` の
  `LANDMARKS` に別に置いてある。
- **二値化は単純閾値ではなく局所コントラスト**（`sub < medianBlur(sub,9) - 20`）。
  黒く塗られた幌の上の線と白地の線を同時に拾うため。閾値55では線が破線化し、80では塗りが混入する。
- **拡大は2倍で足りる**（旧・低解像度版は8倍必要だった）。ぼかしは σ=0.8 まで。
  強くすると近接した2本線が融合して細線化が網目になる。
- **仕上がりの判定は「きれいに見える」ではなく実測**：`hi_svg.py` が毎回、
  出来上がりのベジェから元図のインクまでの距離を距離変換で測って出す（現状 RMS 1.1mm）。

## ハンドルと計器の測り方（`wheel_fit4.py` / `wheel_measure.py`）

リムは窓の中で車体の線と**連結してしまう**ので連結成分では切り出せない。列ごとに落とす手も
**スポークが縦棒なので巻き込む**。効いたのは「**窓の上端と下端の両方に届く列だけ落とす**」。
それでも楕円の自動当てはめは右側の車体線に引かれて 313〜445mm まで振れたので、
最終値は**汚染されていない左側の実測**から決めた。**自動当てはめの数値をそのまま採らないこと。**

## 【2026-08-19 追記】当てはめ方式の差し替えと、「線が途中で切れる」原因

`hi_svg2.py` / `hi_trace2.py` / `poly_look.py` を追加。**`hi_svg.py` は残してある**（比較用）。

```
python hi_svg2.py 34 20 <出力先> [tol] [smooth_w] [thick_len]   # 既定 0.5 / 9 / 90
python hi_trace2.py [gap] [minfrag] [cos]                        # hi_polys2.pkl を作る
python poly_look.py [x0 y0 x1 y1] [zoom] [pkl]                   # 線を1本ずつ色分けして元図に重ねる
```

### `hi_svg2.py`＝「通す」のをやめて「近似する」

`hi_svg.py` は RDP で間引いた点を Catmull-Rom で**必ず通す**ので、芯線化で生まれたギザを1つ残らず拾う。
`hi_svg2.py` は Schneider の最小二乗ベジェ当てはめ（Newton 法の再パラメータ化つき）に替えた。**実測**：

| | 制御点 | 元図とのズレ RMS | bytes |
|---|---|---|---|
| `hi_svg.py`（現行 v7s） | 約1,300 | 1.1mm | 35,110 |
| `hi_svg2.py` tol=0.3 | **397** | **1.0mm** | 14,412 |
| `hi_svg2.py` tol=0.5 | 291 | 1.2mm | 10,813 |
| `hi_svg2.py` tol=1.0 | 213 | 1.5mm | 8,157 |

⚠️**制御点を3分の1に減らしてズレはむしろ小さい**＝現行の節点の大半は形ではなくノイズの再現に使われていた。
うねりは消える。出力は太線/細線の2階層（`thick_len` 以上の線長を太線）。**採用可否はユーザー判断待ち**＝
比較用に `wiring-img/car-top-v8s-t03.svg` と `-t05.svg` を置いてある（未コミット・本番未使用）。

### 「線が途中で切れる」原因＝帯の芯線化で菱形ループに割れる（⛔ここは自動処理では直らない）

`poly_look.py` でフロントガラスまわりを見ると**一目で分かる**。窓の後端の1本の線が
`#21(74) #60(20) #58(21) #64(19) #73(15) #111(6) #125(5) #119(5) #130(4)` の**9断片に割れ、
断片の間に菱形のループができている**。長い `#21` だけが `MIN_LEN` を超えて採用され、あとは捨てられる＝切れる。

- 理由：元図の線は細い1本ではなく**ぼやけた太い帯**。二値化すると幅のある塊になり、芯線化の過程で
  **帯の中で芯が2本に割れては再合流する**。この割れ目がループとして残る。
- Aピラーは元図が二重線・三重線で描かれており、平行な芯線が5本立つ（`#42 #37 #40 #32 #17`）。
- ⛔**端点の近接連結では直らない**＝`hi_trace2.py` の `join_near`（端点が gap 以内かつ正対で継ぐ）を実装して
  実行したが、**継がったのは2組だけ**。断片は切り離されているのではなく**分岐点を共有して枝分かれ**しており、
  「正対する端点どうし」に当てはまらないため。**同じ手を再試行しない。**
- フロントガラス周辺は**線64本のうち採用9本**。捨てた55本は長さ 1.6〜5.2 の交差の残骸。
