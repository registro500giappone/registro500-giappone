# 装備手帳機能 — 実装ハンドオフ（改訂版）

対象サイト: registro500.com
作成日: 2026-07-22
旧称: 車載品アンケート機能 → **「装備手帳」として再定義**

---

## コンセプト

空冷クラシック Fiat 500 オーナーが、出先のトラブルに備えた車載品を**自分の記録として管理するツール**。アンケートは装備手帳の初回入力にすぎない。

- オーナーは自分のガレージページ（登録車両）に装備リストを持つ
- 買い足したら更新する。更新の動機は「自分の記録だから」
- 集計・積載率・リコメンドは、全員の手帳から自動的に生まれる副産物
- 目的は単なる集計ではなく、**回答者への気付きの提供**。「そんな物があるのか」という発見を起こす

一回答えたら終わりのアンケートではなく、常に現在形で更新され続けるデータベースを作る。

---

## 立ち上げ手順（パイロット）

公開前に **友人オーナー2〜3名に先行記入**してもらう。

目的:
1. **推奨度の精査** — 編集部推奨を「実走オーナー数名の検証済み」に格上げする
2. **項目の過不足の検出** — 自由記入から項目マスターへの追加候補を拾う
3. **名品の初期収集** — こだわりの便利工具を「名品」として登録する種にする

条件: パイロット回答は本番データにそのまま繰り入れる。**項目マスターのIDを確定させてから**入力してもらうこと（後からIDが変わると回答が壊れる）。

## 仕様

### 回答形式

- 各項目は **「常時」「随時」の2択**（ラジオ／トグル)
- **未チェック＝積んでいない**。「積んでいない」の明示的な選択肢は置かない
- 「随時」の定義: 遠出・イベント参加・長距離走行時のみ積み込む

### カテゴリ

工具 / パーツ / ケミカル / 非常時対応 / 洗車・その他

### 項目の粒度

原則: **回答の粒度は粗く、リコメンドの粒度は細かく**。

- 回答項目は機能単位（「ソケットレンチセット」「スパナ・メガネ（主要サイズ）」）。銘柄・型番レベルまで細かくすると回答者が照合に疲れて離脱する
- こだわりの便利工具（例: 500のプラグホールに届く薄肉ソケット、エンジンフード内で使える首振りラチェット）は選択肢に埋めず、**自由記入から収集して「名品」として昇格**させる
- `survey_items` に **定番/名品のフラグ**を持たせる。名品はリコメンドや記事で個別に紹介する
- アフィリエイトが最も効くのは名品。「この車のこの作業にはこれ」という具体性はリンクが踏まれる。汎用工具のリンクは踏まれない

### 自由追加欄

各カテゴリ末尾に配置。**行追加式**で以下3点セット:

| 品名 | 常時/随時 | なぜ積むのか |
|---|---|---|

- 初期表示1行、「＋追加」で増加、空欄は無視
- プレースホルダで例示（品名: 「ポイントヤスリ」など）
- 集計後に管理者が手動でマスターへ昇格させる運用

### 一行理由

各項目に「なぜ積むのか」の一行説明を表示。気付きの主動線となるため、回答画面で読める位置に置く（ツールチップ等で隠さない）。

### 経験談セクション

最終セクションに「出先で実際に助かった／困った経験」の自由記述を置く。記事素材として最も価値の高いデータ。

### 車両情報セクション

冒頭で以下を取得（クロス集計用）。**匿名回答でも取る**（匿名分がクロス集計から丸ごと落ちるのを防ぐ）:

- 年式
- 使用頻度（週n回 / 月n回 / 年数回）
- 遠出の頻度

## タイプ分類（車載品思想の観察）

装備データから浮かぶ類型を提示する。雰囲気診断ではなく、**装備構成に表れる故障観の分類**として設計する。命名は整備用語の温度感で、茶化さない。

| タイプ | 装備の特徴 | 思想 |
|---|---|---|
| 現地修理型 | ポイント・ワイヤー類・工具が厚い | 止まっても自力で帰る |
| 予防整備型 | ケミカル・点検系が厚い | そもそも止まらせない |
| 救援前提型 | 非常時対応が厚く工具は薄い | ロードサービスと保険で構える |
| 身軽型 | 最小限 | 近距離しか乗らない割り切り |

分類ロジック: カテゴリ別搭載率のバランスで判定（実装時に閾値を調整）。

活用: 結果画面で「あなたは現地修理型。同型のオーナーはワイヤー類の搭載率が高いが、あなたは未搭載」と返す。**分類がリコメンドの精度説明を兼ねる**。エンタメ性と実用性を同じ仕掛けで両立させる。

## リコメンドロジック（二段構え）

### フェーズ1: 編集部推奨（母数が貯まるまで）

統計母数が閾値（例: 30件）未満の間は、パイロットで精査した**編集部推奨**を返す。

> 「Vベルト — 切れると充電と冷却が同時に止まる。registro500 が最優先で推奨」

一行理由は全項目分あるので追加コストほぼゼロ。サイトの核は「本物のオーナーとしての信頼性」であり、序盤は統計より編集部の声の方が強い。

### フェーズ2: 統計リコメンド（閾値超えで自動切替）

全回答者の項目別積載率を算出 → 未搭載かつ積載率上位の項目を提示。

> 「Vベルト — 積載率78%。あなたは未搭載です」

母数150台規模ではセグメントを細かく切ると数が足りない。当面は全体比較、将来は同年式帯・遠出頻度・同タイプでの絞り込み。

### アフィリエイト導線

リコメンド項目の直下に購入リンク。積載率・推奨という根拠が先にあるため押し付けがましくならない。`survey_items` に **affiliate_url カラムを最初から持たせる**。

## 結果カード

**拡散装置ではなく、記録装置と記事素材**として位置づける（X共有は現状使われていないため）。

- **本人の実用**: 装備一覧を1枚の画像に生成。「車載品チェックリスト」としてグローブボックスやスマホに入れて使える
- **サイト内展示**: 公開設定にしたオーナーの装備手帳・タイプ分類をガレージページに表示。回遊はサイト内で完結
- **拡散**: カードに頼らず、集計記事（「150台の車載品、最も積まれていない必需品は◯◯だった」）を note → サイトの既存ファネルに乗せる
- X共有ボタンは隅に置く程度で可

## データ設計

### 必須要件

- **回答は個別レコードで保存**（項目ID / 常時・随時 / 回答日時）。集計値のみの保持は不可
- **項目マスターはDB化**。昇格で項目を追加しても既存回答が壊れない構造
- **未回答と未搭載を区別**。カテゴリごとに完了フラグ。未チェックを一律「未搭載」と扱うと途中離脱者のデータが集計を汚染する
- **最新状態＋変更履歴**。装備手帳は現在の状態を表し、変更は履歴として残す。「1年前の自分との比較」をコンテンツ化できる
- **匿名回答可**。ログイン時のみ登録車両に紐付け。匿名でも車両情報セクションは取る

### テーブル構成（案）

```
survey_items            項目マスター
  id, category, name, reason, sort_order, is_active,
  item_class ('standard'|'meihin'),   -- 定番/名品フラグ
  affiliate_url (nullable)

survey_responses        手帳（回答セッション）
  id, user_id (nullable), vehicle_id (nullable),
  is_anonymous, model_year, usage_freq, longtrip_freq,
  created_at, updated_at

survey_answers          個別回答（最新状態）
  id, response_id, item_id, frequency ('always'|'occasional')

survey_answer_history   変更履歴
  id, response_id, item_id, frequency, changed_at, change_type ('add'|'update'|'remove')

survey_category_status  カテゴリ完了フラグ
  response_id, category, completed

survey_custom_items     自由追加項目
  id, response_id, name, frequency, reason, promoted_to_item_id (nullable)

survey_experiences      経験談
  id, response_id, body, created_at
```

## 項目マスター（シードデータ）

一行理由は空冷前提。水冷126専用項目（クーラント等）は除外済み。**パイロットでの精査により増減する前提の初期案**。

### 工具

| 品名 | 一行理由 |
|---|---|
| プラグレンチ（14mm・深さのあるもの） | 現地でのプラグ交換・清掃に必須 |
| シックネスゲージ | ポイントギャップ調整用 |
| 検電テスター | 電装トラブルの切り分けが一気に速くなる |
| スパナ・メガネ（主要サイズ 10/11/13/17mm） | 500の主要ボルトはこのサイズでほぼ足りる |
| マイナスドライバー（大小） | 旧車のネジはマイナスが多い |
| ラジオペンチ・ニッパー | 配線処理と針金作業に |
| 針金・タイラップ | 落ちかけた部品の応急固定に |
| 自己融着テープ | ホース・配線の応急補修に |
| 車載ジャッキ | 純正の有無を確認しておきたい |
| 輪止め | ジャッキアップ時の安全確保 |
| ヘッドライト（頭部装着型） | 両手が使える照明が現場では効く |
| 整備マット | 路上に寝転がる前提の装備 |
| 軍手・ウエス | 消耗品だが無いと何も始まらない |

### パーツ

| 品名 | 一行理由 |
|---|---|
| Vベルト | 切れると充電と冷却が同時に止まる。空冷最大の弱点 |
| ポイント | 出先で最も多い不動原因のひとつ |
| コンデンサー | ポイントと同時に交換したい |
| スパークプラグ | かぶり・失火時の交換用 |
| プラグコード | 経年でリークする |
| デスビキャップ | クラック・カーボン汚れで失火 |
| ローター | デスビキャップとセットで |
| ヒューズ（ガラス管） | 現代の規格と異なるため入手困難。必携 |
| 電球一式 | ヘッドライト・ウインカー・テール |
| 燃料ホース＋ホースバンド | ゴムは経年で必ず劣化する |
| アクセルワイヤー | 切れたら自走不能 |
| クラッチワイヤー | 同上 |
| ガスケット類 | 応急の分解を伴う修理時に |
| ボルト・ナット・ワッシャー | 振動で落とす前提の消耗品 |
| スペアタイヤ（空気圧点検済み） | 積んでいても空気が無ければ意味がない |

### ケミカル

| 品名 | 一行理由 |
|---|---|
| エンジンオイル | 空冷は油温＝冷却。減りに敏感になるべき |
| ブレーキフルード | 漏れの応急補充に |
| パーツクリーナー | 汚れたまま触れない箇所の清掃に |
| 潤滑スプレー | 固着したネジ・可動部に |
| 接点復活剤 | 旧車の不調はまず接点を疑う |
| 液体ガスケット | 漏れの応急処置に |
| マフラーパテ | 排気漏れは車内に一酸化炭素が回る |
| ガソリン携行缶 | 燃料計の精度が低い車両では現実的な備え |
| パンク修理剤 | スペア交換が難しい状況の保険 |

### 非常時対応

| 品名 | 一行理由 |
|---|---|
| 発煙筒（期限確認） | 期限切れが非常に多い |
| 三角表示板 | 高速道路では法定義務 |
| ブースターケーブル | ダイナモ車はバッテリー上がりが起きやすい |
| 牽引ロープ | 自走不能時の最終手段 |
| 携帯空気入れ | スペアタイヤの空気圧低下に対応 |
| モバイルバッテリー | スマホが唯一の通信手段 |
| ロードサービス連絡先 | 会員証と番号を車内に |
| 保険証券 | 事故時に必要 |
| 配線図・整備マニュアル | 現場での判断材料になる |
| 反射ベスト | 夜間の路肩作業で命に関わる |
| 雨具 | 路上作業は天候を選べない |
| 飲料水 | 待機時間が長引くことがある |

### 洗車・その他

| 品名 | 一行理由 |
|---|---|
| マイクロファイバークロス | オイル汚れの拭き取りにも使える |
| ガラスクリーナー | 視界確保は安全に直結 |
| 車検証・自賠責 | 携行が法定義務 |
| ETC・小銭 | 旧車は電装トラブルでETCが落ちることがある |
| スマホホルダー・充電ケーブル | ナビと通信の確保 |

## 実装上の注意

- 同義語の名寄せ（「タイラップ」「結束バンド」「インシュロック」）は人力前提。管理画面に統合機能があると運用が楽（フェーズ2）
- 45項目を1問ずつ並べると回答が持たない。カテゴリ単位で一覧表示し、タップだけで完結する UI にする
- スマホ回答が主体になる想定でレイアウトを設計
- 自由追加項目の出現回数が多いものは選択肢の設計漏れであり、コミュニティが実地で学んだ知恵の証拠。優先的にマスターへ昇格させる
- 名品候補は昇格時に `item_class='meihin'` を付与し、リコメンド・記事・アフィリエイトで個別展開する
