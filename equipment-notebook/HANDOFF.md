**根因1＝カテゴリ間で項目数が違うのに「率」を直接比較している**。有効項目は工具23／パーツ20／ケミカル8／非常時12と偏りが大きく、**項目数の少ないケミカルは率が跳ねやすい**。MEXは工具42項目＋自由追加16の最重装備なのに、ケミカル率.75 > mechScore.558 で `yobou`（予防整備型）に落ちた。

**根因2＝身軽型の閾値 `overallLoaded <= 2` が厳しすぎ、最後のfallbackが `genchi`**。napdesignは5項目（工具のみ）なのに「現地修理型」と判定される。**判定に失敗したとき最も重い型に落とすのは失礼**であり、fallbackは身軽型にすべき。

**【2026-07-24 ユーザー承認・実装/デプロイ済 commit `286c389`】率でなく実数で判定する決定木に置き換えた**：
```
mech = 工具数 + パーツ数 (最大43) / emg = 非常時対応数 (最大12) / chem = ケミカル数 (最大8)
1. mech >= 15                  → 現地修理型
2. chem >= 5 かつ mech < 15    → 予防整備型
3. emg >= 4 かつ mech <= 8     → 救援前提型
4. それ以外                     → 身軽型（fallback＝最も控えめな型に落とす）
```
この式を上表に当てると6件すべて納得のいく型になる（MEX/スシオ/ぱそた/otsuka＝現地修理型、fiat_takeshi＝救援前提型、napdesign＝身軽型）。**閾値はn=6の暫定値なので、回答が増えたら見直す前提**。

**「合理的レッカー利用タイプ」＝救援前提型そのもの（ユーザー提起・重要）**：何でも自分で対応するのでなく、軽く対処できる装備だけ積んで、あとは割り切ってロードサービスを呼ぶ層。**パイロット5名は全員フル満載型に寄った極端なサンプルで、実際にはこの層が最も多い可能性が高い**。現行の説明文「ロードサービスと保険で構える。非常時対応の装備が、その安心を支えています。」は受け身に読めるため、**本人の能動的な合理判断として書き直す**（身軽型の「割り切り」と語彙が重複しているので、身軽型＝ほとんど積まない／救援前提型＝軽い装備は積んで使い分ける、と書き分ける）。
→ **実装済**：救援前提型 desc =「直せる範囲は自分で、無理はしない。手当てと救援の使い分けが、いちばん現実的な構えです。」
