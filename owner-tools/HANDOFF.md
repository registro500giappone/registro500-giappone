# みんなのおすすめ工具（オーナー投稿）— 引き継ぎ書

登録オーナーが「おすすめの工具」を写真と一言で紹介し、工具ごとに並べて読めるページ。
2026-10-07 起票（登録オーナーからのリクエストが発端）。

## 0. 経緯

- 既存の `/goods` は管理人が作った固定ページで、オーナーは投稿できない。
- 既存の車載手帳（`/equipment`）には自由項目（工具29件）とメモ（工具53件）があり、中身はすでに「おすすめ工具の紹介」になっていた。ただし入口の名前が「車載」で、ガレージ用の工具の置き場が無く、声が手帳1冊ごとに散らばって読めない。
- 実データで一覧のモックを作って確かめた結果、手帳のメモは一言だけのもの（「忘れた」「色々」等）が多く、同じ工具でも書き方がばらばらだった。また、手帳のメモを広告リンクの横に転載するには本人の了解が要る。→ **投稿の器を先に作り、手帳の声は本人の了解を取れた分だけ移す**順に決めた。

## 1. 確定事項（ユーザー決定・2026-10-07）

1. 投稿できるのは**ログイン済みの登録オーナーだけ**（自分の車に紐づけて投稿＝`owns_car()`）。**個別の承認は不要**＝投稿したらすぐ一覧に出る。
2. **写真を扱う**。投稿フォームでは**写真1枚を必須**にする（工具は写真で伝わるため）。DB上は NULL を許す＝手帳から移した声は写真なしで載る。
3. 対象は**車に積む工具も、ガレージで使う工具も**両方。
4. **Amazonのアフィリエイトリンクを付ける**。付けるのは管理人だけ（投稿者は URL を入れない）。
5. 車載手帳から声を移すときは、**書いた本人へ個別に了解を取る**。了解が取れた分だけ、管理人が代わりに登録する。
6. 進め方＝**投稿の器が先** → 手帳からの移行 → 見た目の仕上げ。

## 2. 不変条件（勝手に変えない）

- ⛔**導線を付けない**（メニュー・トップ・他ページからのリンク・sitemap）。公開の判断はユーザーが出す。それまで `noindex`。
- ⛔投稿者に購入リンクを入力させない（タグのすり替え・規約違反の防止）。`amazon_url`・`tool_key`・`is_hidden` は**管理人だけが書ける**（DBトリガーで強制）。
- 投稿時に**同意チェック**を必須にする：「この紹介はサイトで公開され、管理人が購入リンク（Amazon・PR）を添えることがあります」。
- 表示はすべて `textContent`（保存型XSSを作らない）。
- Amazonリンクの規則（事前確認リスト）：**ページ専用タグ**を使う／`rel="nofollow sponsored"` は**リンクを生成する箇所で直接付ける**（非同期描画のため一括付与は間に合わない）／PR表記／開示文のIDはリンクの `tag=` から動的に取る／「最安」等の断定をしない／価格を載せない。
- 「順位」「人気ランキング」を作らない。数として出すのは「◯台が使用」だけ。
- 新しいページの meta：`og:image`＝`og/site-ja.png`（1200×630）・`twitter:card`＝`summary_large_image`・GA4 タグ（`python py/check_pages.py` で確認）。

## 3. データ

テーブル `public.owner_tools`（migration＝`owner-tools/schema_2026-10-07.sql`）

| 列 | 意味 |
|---|---|
| `id` uuid | |
| `car_id` text | 投稿した車（`cars.document_id`）。RLS は `owns_car(car_id)` |
| `name` text | 工具名（1〜80字）。メーカー・型番まで書くことを勧める |
| `category` text | `ignition`点火・キャブ／`electric`電装／`chassis`足まわり・ジャッキ／`wrench`レンチ・ソケット・ドライバー／`measure`測る・調べる／`misc`あると助かる小物 |
| `usage` text | `carry`車に積む／`garage`ガレージで使う／`both`両方 |
| `comment` text | 一言（1〜400字）。何に使うか・なぜ良いか |
| `photo_url` text | Firebase Storage `tools/{carId}/{時刻}.jpg` の URL（長辺1600px・JPEG 0.85） |
| `consent_at` timestamptz | 同意した時刻（必須） |
| `source` text | `post`本人の投稿／`notebook`手帳から了解を得て移したもの |
| `tool_key` text | 管理人が付ける「同じ工具」のまとめ鍵（NULL＝単独のカード） |
| `amazon_url` text | 管理人だけ。ページ専用タグ入りの URL |
| `is_hidden` boolean | 管理人だけ。不適切な投稿を伏せる |
| `created_at` / `updated_at` | |

- 読み取り：誰でも（`is_hidden = false` の行）。持ち主と管理人は自分の伏せられた行も読める。
- 書き込み：`is_admin() OR owns_car(car_id)`。管理人専用列は非管理人が変えられない（トリガー `owner_tools_guard`）。
- Firebase Storage：`storage.rules` に `match /tools/{allPaths=**}`（読み取り自由・新規作成のみ・10MB以下・画像のみ）。⚠️rules は**ローカルPCから `firebase deploy --only storage`**。

## 4. 画面

- `/tools`（`tools.html`）一覧：モックA（`registro500-notes\owner-tools\mock-a.html`）の形。工具ごとのカード（写真・工具名・「◯台が使用」・分類・積む／ガレージ・オーナーの一言（ハンドル名・型式→車両ページ）・Amazonボタン＋PR）。上部に「＋ わたしの一本を紹介する」と分類の切り替え。`tool_key` が同じ投稿は1枚のカードにまとめ、写真は最初の投稿のものを使う。
- `/tools-edit`（`tools-edit.html`）投稿：ログイン必須。自分の車が2台以上なら選ばせる。工具名・分類・積む／ガレージ・一言・写真・同意。自分の投稿の一覧・修正・削除もここ。

## 4b. 実装状況（2026-10-07）

- DB：`owner_tools` 適用済。トリガー `owner_tools_guard` は**管理人（`is_admin()`）とサーバー側の権限（postgres・service_role＝MCPやスクリプト）だけが全列を書ける**（第2 migration `owner_tools_guard_allow_service`）。持ち主・他人の車・未ログインの3通りをロールバック付きで試験済み。
- Storage：`tools/` の rules を deploy 済（`storage.rules` は `.gitignore` 対象＝repo には無い・ローカルPCにだけある）。
- 画面：`tools.html`・`tools-edit.html`（noindex・導線なし）。まとめたカードの見出しは「購入リンクの付いた投稿の名前 → 無ければいちばん長い名前」。
- 管理人の作業はSQLで行う（管理画面は作っていない）：まとめる＝同じ `tool_key` を入れる／購入リンク＝`amazon_url`／伏せる＝`is_hidden = true`。
